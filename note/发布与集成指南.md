# 发布与集成

> 本文档适用于 Watercolor UI 组件库的 NPM 发布、CI/CD 自动化、迁移集成、常见问题等相关流程，帮助团队成员高效、安全地进行包发布与项目集成。

---

## 1. 文档说明

Watercolor UI 支持现代化的 NPM 发布、自动化 CI/CD、与 Material-UI 的平滑迁移，适用于团队协作与企业级项目。

## 2. NPM 发布流程

### 2.1 环境要求
- Node >= 18.x（建议 nvm 管理多版本）
- npm >= 9.x（或 pnpm/yarn）
- git >= 2.30（建议开启 GPG 签名）

### 2.2 登录与权限
- 首次登录：`npm adduser` 或 `npm login`
- 组织包需有发布权限：`npm access grant read-write @watercolor:developers <npm-username>`

### 2.3 发布前检查
- 检查 package.json 入口、files、author、repository、keywords 等字段
- 检查 .npmignore 排除无关文件（如测试、文档、Storybook、源码等）
- 运行 `npm run check-publish` 检查发布文件
- 确认 dist/ 目录下构建产物完整

### 2.4 构建与发布命令
- 构建 Vue 包：`yarn build:vue` 或 `npm run build:vue`
- 构建 React 包：`yarn build:react`
- 自动发布（推荐）：
  ```bash
  npm run release:patch   # 补丁版本
  npm run release:minor   # 次要版本
  npm run release:major   # 主要版本
  ```
- 手动发布：
  ```bash
  npm run check-publish
  npm version patch/minor/major
  npm run build
  npm publish
  git push --follow-tags
  ```

### 2.5 版本管理
- 遵循 [SemVer](https://semver.org/lang/zh-CN/) 规范
- 破坏性变更 +1 主版本，新增功能 +1 次版本，修复/文档 +1 补丁
- 推荐使用 changesets 或 conventional commits 自动生成 CHANGELOG.md

## 3. CI/CD 自动化发布

### 3.1 Git Tag 与 Changelog
- 发布前提交并打 tag：
  ```bash
  git add -A
  git commit -m "chore(release): v1.2.0"
  git tag v1.2.0
  git push origin main --tags
  ```
- 自动生成 changelog：`npm run changelog`

### 3.2 GitHub Actions 示例
`.github/workflows/release.yml`：
```yaml
name: Release
on:
  push:
    tags:
      - 'v*.*.*'
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: pnpm/action-setup@v2
        with:
          version: 8
      - name: Install deps
        run: pnpm install --frozen-lockfile
      - name: Build
        run: |
          pnpm build:vue
          pnpm build:react
      - name: Publish
        run: pnpm publish --access public
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

## 4. 迁移与兼容

### 4.1 迁移策略
- 推荐优先使用兼容层迁移（零代码修改，直接替换 import 路径）
- 支持渐进式组件替换与完整重构

#### 兼容层迁移示例
```js
// 之前
import { Button, TextField } from '@mui/material'
// 现在
import { Button, TextField } from 'watercolor-ui/mui-compat'
```

#### 渐进式替换
```js
// 阶段1：兼容层
import { Button } from 'watercolor-ui/mui-compat'
// 阶段2：原生组件
import { Button } from 'watercolor-ui'
```

#### 样式与主题迁移
- 确保引入 Watercolor UI 样式：`import 'watercolor-ui/styles'`
- 主题配置可兼容 Material-UI 语法

#### 组件映射表
| Material-UI 组件 | Watercolor 兼容组件 | 状态 |
|-----------------|-------------------|------|
| Accordion | Accordion | ✅ 完全兼容 |
| Alert | Alert | ✅ 完全兼容 |
| ... | ... | ... |

## 5. 图标集成说明

- 推荐统一用 Icon 组件封装，便于主题和样式统一
- 支持 Lucide、Heroicons、Tabler、Phosphor、Feather 等主流图标库
- Vue 用法：
  ```vue
  <IconVue library="lucide" name="heart" size="md" />
  <IconVue library="heroicons" name="heart" variant="outline" />
  ```
- React 用法：
  ```jsx
  <IconReact library="lucide" name="Heart" size="md" />
  <IconReact library="heroicons" name="heart" variant="solid" />
  ```
- 详细见 ICON_INTEGRATION_GUIDE.md

## 6. 常见问题与解决方案

| 现象 | 解决方案 |
| ---- | -------- |
| 发布403 | 检查 npm Token 权限、包名所有权、组织作用域 |
| peer dependency 警告 | 发布前确保 peerDependencies 只包含当前框架 |
| umd 体积过大 | 检查 external 配置，仅保留 ESModule |
| TS 类型丢失 | 确认 vite-plugin-dts 插件启用，insertTypesEntry 为 true |
| 构建失败 | 检查依赖、配置、Node 版本 |
| 样式不一致 | 检查样式文件导入、变量覆盖 |
| 图标不显示 | 检查图标名、库名、SVG 是否正确 |

## 7. 最佳实践与团队协作建议

- 发布前本地完整测试、文档同步更新
- 版本号递增与 changelog 保持一致
- 推荐自动化发布，减少人为失误
- 组件库与业务项目解耦，避免循环依赖
- 发布后及时在 npm/GitHub 验证包可用性
