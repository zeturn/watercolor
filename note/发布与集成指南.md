# 发布与集成指南

Watercolor UI 通过 GitHub Actions 和 npm Trusted Publishing 发布。正式版本不应在本地逐包执行 `npm publish`。

## 发布前检查

需要 Node.js 24 与 lockfile 对应的 npm。在干净工作树中执行：

```bash
npm ci
npm run lint
npm run typecheck
npm test -- --run
npm run audit:theme
npm run audit:composition
npm run audit:visual
npm run audit:api
npm run test:package
npm run build-storybook:vue
npm run build-storybook:react
npm run visual:recipes
npm run docs:build
```

`test:package` 会构建实际 npm 产物、校验 `exports` 与包内文件，并在干净的 React、Vue 和 core 消费项目中安装 tarball。

## 版本与标签

根包与 `packages/*` 中所有可发布包必须共用同一版本号。标签必须与版本完全一致；例如所有 manifest 为 `1.2.1` 时，只能使用 `v1.2.1`。

使用仓库发布脚本完成版本提交和标签：

```bash
npm run release:patch
```

脚本不会自动收集工作树中的未知文件。发布前应先审阅并提交当前改动。

## GitHub Actions 发布门禁

`.github/workflows/publish.yml` 只允许从 SemVer tag 发布；手动触发同样必须选择 tag。工作流会：

1. 校验 tag 与所有可发布 package version。
2. 执行 lint、类型、测试、契约审计、clean-room 安装、Storybook 视觉矩阵和文档构建。
3. 先发布图标包和 core，确认 core 在 npm 可见后，再发布 React、Vue 和 installer。

任何门禁失败都会在 npm publish 之前终止工作流。
